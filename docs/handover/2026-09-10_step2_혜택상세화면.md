## 1. 이번 작업에서 한 일

1. **`/benefits/:id` 혜택 상세 화면 전체 구현** (Figma Image 2 기준)
   - 상단바: 뒤로가기, "혜택 상세" 타이틀, **상세/요약 토글**
   - 카드 헤더: 제목, 즐겨찾기(스크랩)/공유 아이콘, 카테고리 뱃지, 상태 뱃지(D-day/상시), 신청기간
   - **상세 모드**: 정책번호, 정책분야, 지원내용, 사업 신청기간, 신청자격, 신청방법, 신청 사이트(링크), 제출서류
   - **요약 모드**: `src/utils/summarize.ts`의 규칙 기반 로직으로 핵심 내용만 재구성해서 보여줌
   - 하단 고정 "신청하기" 버튼 (외부 링크 새 탭 이동)
2. **중복 지원 불가 혜택 비교 안내 배너**: `comparisonGroupId`가 있는 혜택이면 그룹 안내 문구 노출 (실제 "더 유리한 혜택 비교" AI 로직은 즐겨찾기 화면 구현 시 연결 예정)
3. **AI 비교 추천 프롬프트**: `hasVariants: true`인 혜택(K패스)은 "상세 혜택을 비교하시겠어요?" 배너 + "비교하기" 버튼 노출 → `/benefits/:id/compare`로 이동
4. **`/benefits/:id/compare` 비교 화면**: 아직 ComingSoon 플레이스홀더 (다음 단계 후보)
5. **레이아웃 구조 변경**: 혜택 상세처럼 자체 상단바가 필요한 화면을 위해 `SubPageLayout`(공통 Header 없이 BottomNav만 유지) 신설. `App.tsx` 라우팅을 AppLayout / SubPageLayout / BareLayout 세 그룹으로 재정리
6. **최근 본 공고 연동**: 상세 화면 진입 시 `useRecentViewStore.addRecentView()` 자동 호출 (단, "최근 본 공고" 화면 자체는 아직 ComingSoon)
7. **검증**: `npx tsc -b`, `npm run build` 통과 확인

## 3. 다음 작업자가 알아야 할 것

- **"요약" 모드는 실제 AI 호출이 아닙니다.** `src/utils/summarize.ts`에 규칙 기반으로 텍스트를 재구성하는 임시 로직만 있습니다. 파일 상단에 TODO 주석으로 API 명세서 경로(`GET /benefits/{id}/summary`)를 남겨뒀습니다.
- **레이아웃이 3종류로 나뉩니다**: `AppLayout`(헤더+하단네비, 홈/즐겨찾기/캘린더 등), `SubPageLayout`(하단네비만, 혜택상세처럼 자체 상단바 있는 화면), `BareLayout`(둘 다 없음, 로그인/온보딩). 새 화면 추가 시 어디에 속하는지 먼저 판단하세요.
- **중복 지원 불가 혜택 비교 배너는 지금 "무조건" 뜹니다** (comparisonGroupId만 있으면). 원래 기획은 "같은 그룹의 다른 혜택도 스크랩했을 때"만 떠야 하므로, 즐겨찾기 로직 붙일 때 조건을 좁혀야 합니다.
- 목업 혜택 중 `b-003`(국가근로장학금)이 `comparisonGroupId` 테스트용, `b-005`(K패스)가 `hasVariants` 테스트용입니다. 실제 화면 확인 시 이 두 개로 확인하세요.
