## 1. 이번 작업에서 한 일

### 공통
- `src/components/ui/CategoryIcon.tsx` 신설 — 카테고리별 색상 아이콘 아바타(생활비=핑크 집, 교육=로즈 하트, 장학금=민트 학사모, 취업·창업=블루 서류가방, 주거=퍼플 건물)
- `BenefitCard`에 `showCategoryIcon` prop 추가 — 즐겨찾기/캘린더 리스트에서만 아이콘 노출 (홈 화면 리스트는 기존처럼 아이콘 없음, Figma와 동일)

### 알림 내역 (`/notifications`)
- 탭 스타일을 세그먼트(캡슐) → **언더라인 탭**으로 변경 (Figma와 동일)
- 뱃지 스타일을 채워진 배경 → **아웃라인**으로 변경 (진행중: 민트 테두리, 마감: 회색 테두리)
- **별 아이콘**: 스크랩한 혜택과 관련된 알림에만 노출 (`mockNotifications`에 `starred` 필드 추가)
- **시계 아이콘**: 마감/진행 관련 뱃지가 있는 알림에 노출

### 캘린더 (`/calendar`)
- 날짜 아래 단순 점(dot) 표시 → **신청기간을 가로 막대(bar)로 시각화**하도록 전면 재작성
  - 주(week) 단위로 렌더링하고, 각 혜택의 신청기간이 그 주와 겹치는 구간만큼 컬러 바를 그림 (`grid-column-start/end` 활용)
  - 상시(always) 혜택은 바 표시 대상에서 제외
  - 마감임박 리스트 카드에 `CategoryIcon` 추가

### 즐겨찾기 (`/scraps`)
- "즐겨찾기 한 혜택" 리스트에 `CategoryIcon` 추가 (AI 추천 TOP3에는 기존처럼 번호만, 아이콘 없음 — Figma와 동일)

### 프로필 (`/profile`)
- 닉네임 아래 서브타이틀을 학력 원문 대신 짧은 신분 라벨로 표시 (`대학교 재학` → `대학생` 등, `shortStatusLabel` 함수)

### 온보딩 (`/onboarding`)
- "기본 정보"/"상황 정보" 섹션을 **테두리 박스로 감싸도록** 변경 (`SectionBox` 컴포넌트)
- 나이/거주지/소득분위/학력/전공/취업여부를 텍스트 입력 → **드롭다운(select)** 으로 변경, 임의 옵션 목록 구성 (실제 서비스에서는 행정동 코드/표준 코드 등으로 교체 필요)
- 상세주소/학교 필드에 돋보기(검색) 아이콘 추가 (실제 주소/학교 검색 API 연동은 미구현, 아이콘만)
- 모든 필드를 테두리 없는 **채워진 배경 스타일**(`.input-filled`)로 변경 — 로그인 화면의 테두리 입력창(`.input`)과는 의도적으로 다르게 유지 (Figma에서 두 화면의 필드 스타일이 다름)
- "저장 하기" 버튼을 각진 사각형 → **완전한 pill(알약) 모양**으로 변경

## 2. 아직 안 한 일 / 알려진 한계

- 온보딩의 드롭다운 옵션(거주지, 전공 등)은 **임의로 구성한 목업 목록**입니다. 실제로는 행정구역 표준 코드, 학과 분류 코드 등을 붙여야 합니다.
- 캘린더의 기간 막대는 **같은 주(week)에서만 세그먼트가 끊기는 방식**입니다. 여러 혜택이 같은 주에 겹치면 막대가 위아래로 쌓이는데, 개수가 많아지면(5개 이상) 색상이 순환(`BAR_COLORS` 5개)되므로 겹칠 수 있습니다. 실제 서비스에서는 카테고리별 고정 색상 등으로 정리하는 게 좋습니다.
- 로그인 화면(`/login`)은 이번 정밀도 개선에서 **의도적으로 손대지 않았습니다** — 이번에 받은 Figma 이미지에 로그인 화면이 포함되지 않았기 때문입니다. 이전 Figma 이미지 기준 그대로 유지됩니다.

## 3. 다음 작업자가 알아야 할 것

- `CategoryIcon`은 `BenefitCategory` 5종 전부에 매핑되어 있습니다 (`src/components/ui/CategoryIcon.tsx`). 새 카테고리를 추가하면 이 파일도 같이 갱신해야 타입 에러가 안 납니다.
- 캘린더 바 색상(`BAR_COLORS`)과 카테고리 아이콘 색상은 현재 **서로 다른 팔레트**를 씁니다 (바는 순환 색상, 아이콘은 카테고리 고정 색상). 디자인 통일이 필요하면 다음 단계에서 하나로 합치는 걸 고려하세요.
- `.input`(테두리형)과 `.input-filled`(채워진형) 두 스타일이 공존합니다. 새 폼 필드를 만들 때 어느 화면인지 보고 골라 쓰세요 (로그인/일반 폼=`.input`, 온보딩류=`.input-filled`).
