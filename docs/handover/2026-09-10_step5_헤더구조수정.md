# Step 5. 헤더 구조 버그 수정 (알림/즐겨찾기/프로필/캘린더) — 작업 요약 & 인수인계

- **작업일**: 2026-09-10
- **작업자**: Claude (AI 페어프로그래머)
- **작업 시작 전 확인**: AGENT.md, `docs/handover/2026-09-10_step4_UI정밀도개선.md` 읽고 시작함
- **계기**: 사용자가 "알림내역/즐겨찾기/프로필 UI가 깨지는 것 같다, 참고 이미지대로 정확히 반영해달라"고 요청

## 1. 원인

Figma를 다시 확인한 결과, **홈 화면만 공통 Header(Opiki 로고 + 캘린더/알림/프로필 아이콘)를 쓰고, 나머지 화면(캘린더/즐겨찾기/알림내역/프로필/혜택상세 등)은 전부 "뒤로가기 + 가운데 정렬 타이틀" 상단바를 사용**하는 구조였습니다.

그런데 Step 3 작업 때 캘린더/즐겨찾기/알림내역/프로필/최근본공고/AI상담원을 `AppLayout`(공통 Header 사용) 그룹에 넣어버려서, 이 화면들에 Figma에 없는 "Opiki 로고+아이콘" 헤더가 뜨고 있었습니다. 이게 "깨져 보인다"는 문제의 원인이었습니다.

## 2. 이번 작업에서 한 일

1. **`src/components/layout/SubPageHeader.tsx` 신설** — 뒤로가기 아이콘 + 가운데 정렬 타이틀 + (선택) 우측 슬롯으로 구성된 공용 상단바. 혜택상세의 "상세/요약" 토글처럼 화면마다 다른 우측 요소는 `right` prop으로 전달.
2. **`App.tsx` 라우팅 재구성**: `AppLayout`(공통 헤더)은 **홈(`/`) 하나만** 사용하도록 축소. 나머지 전부(`/benefits/:id`, `/benefits/:id/compare`, `/scraps`, `/calendar`, `/notifications`, `/ai`, `/recent`, `/profile`)는 `SubPageLayout`(자체 상단바 + 하단 네비 유지)으로 이동.
3. **화면별 적용**:
   - 알림내역, 즐겨찾기, 프로필, 캘린더, 최근 본 공고, AI 상담원: 각자 있던 임시 제목(`<h1>`)이나 없던 헤더를 `SubPageHeader`로 교체
   - 혜택상세, 비교하기: 기존에 인라인으로 작성했던 뒤로가기+타이틀 코드를 `SubPageHeader`로 리팩터링 (기능/모양은 동일, 코드 중복만 제거)
4. **검증**: `npx tsc -b`(noUnusedLocals 켜져 있어 미사용 import도 같이 잡힘), `npm run build` 통과 확인

## 3. 다음 작업자가 알아야 할 것

- **새 화면을 추가할 때 헤더를 고르는 기준**: 홈처럼 "브랜드 로고 노출이 필요한 최상위 화면"이 아니라면 거의 항상 `SubPageLayout` + `SubPageHeader`를 씁니다. `AppLayout`(공통 Header)은 원칙적으로 홈 전용이라고 생각하세요.
- `SubPageHeader`의 `right` prop은 `min-w-6`인 빈 div가 기본값이라, 우측에 아무것도 없어도 타이틀이 정확히 중앙에 오도록 좌우 균형을 맞춰줍니다. 우측에 뭔가 넣을 때도 이 prop만 채우면 됩니다.
- AI 상담원 화면의 헤더는 원래 Sparkles 아이콘이 있었는데, 이번에 공용 `SubPageHeader`로 통일하면서 아이콘은 빠졌습니다. AI상담원 전용 Figma 디자인은 아직 확보되지 않았으니, 나중에 해당 디자인이 오면 다시 확인이 필요합니다.
