# Opiki 기술 스택 & 아키텍처 문서

## 1. 전체 아키텍처 개요

```
[Client: iOS/Android(or 모바일 웹)]
        │
        ▼
[API Gateway / Backend Server]
        │
   ┌────┼─────────────┬───────────────┐
   ▼    ▼              ▼               ▼
[Auth]  [Benefit       [AI Service     [Notification
        Service]        (요약/추천/     Service(FCM)]
                         상담원)]
        │
        ▼
     [DB (RDB)]
        │
        ▼
[외부 연동: 공공데이터포털/각 기관 공고 크롤링·API,
 OS 캘린더 연동, (보류) 마이데이터 API]
```

## 2. 계층별 기술 스택 제안

| 계층 | 기술(예시) | 비고 |
|---|---|---|
| 프론트엔드(앱) | Flutter 또는 React Native | 크로스플랫폼으로 iOS/Android 동시 대응 |
| 프론트엔드(웹, 선택) | React + Tailwind | MVP를 웹으로 먼저 검증 시 |
| 백엔드 | Node.js(Express/NestJS) 또는 Spring Boot | 팀 숙련도에 따라 선택 |
| DB | PostgreSQL 또는 MySQL | JSON 컬럼 활용(자격조건 매칭) 고려 시 PostgreSQL 유리 |
| AI 연동 | Anthropic/OpenAI API (요약, 상담원, 추천 로직 보조) | 프롬프트 기반 + 서버단 규칙(자격조건 필터링) 병행 권장 |
| 알림 | Firebase Cloud Messaging(FCM) | iOS/Android 통합 푸시 |
| 캘린더 연동 | iOS: EventKit / Android: CalendarContract, 또는 .ics export | 네이티브 권한 필요 |
| 인증 | JWT + 소셜로그인(카카오/구글 등) | |
| 인프라 | AWS(EC2/RDS/S3) 또는 유사 클라우드 | 학생 프로젝트는 프리티어/저비용 구성 우선 |
| 크롤링/데이터수집 | Python(BeautifulSoup/Scrapy) 배치 또는 공공데이터포털 API | 혜택 원문 수집용 |

## 3. AI 기능별 처리 방식

| 기능 | 처리 방식 |
|---|---|
| 공고 요약 | 원문 → LLM 요약 프롬프트 → 결과 캐싱(BenefitSummary 테이블) |
| 맞춤 추천 | 1차: 서버 로직으로 자격조건(JSON) 필터링 → 2차: LLM으로 우선순위/추천 사유 문구 생성 |
| 비교 추천(K패스형) | 조건 규칙(BenefitVariant.condition_rule) 매칭 후 LLM이 설명 생성 |
| AI 상담원 | 대화 컨텍스트 + 사용자 프로필을 프롬프트에 포함 → 관련 혜택 검색 결과를 함께 반환(RAG 형태 권장) |

## 4. 외부 연동 관련 참고사항

- **혜택 원문 수집**: 공공데이터포털, 정부24, 지자체 청년포털 등 공식 API 우선 활용. API 미제공 기관은 크롤링 시 각 사이트 이용약관/robots.txt 확인 필요
- **OS 캘린더 연동**: 네이티브 앱에서만 가능(모바일 웹에서는 제약이 큼 → .ics 다운로드 방식으로 대체 가능)
## 5. MVP 범위 제안

| 단계 | 포함 기능 |
|---|---|
| MVP (1차) | 혜택 목록/상세/요약, 회원가입/온보딩, 맞춤추천, 스크랩, 캘린더(자체 뷰) |
| 2차 | 푸시 알림, AI 상담원, 비교 추천, 최근 본 공고 |
| 3차 | 기본 캘린더 앱 연동, 알림 히스토리 고도화 |
